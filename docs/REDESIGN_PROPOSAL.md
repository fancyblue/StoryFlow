# StoryFlow 全站調整與圖文重新設計提案

> 狀態：候選／待驗證（2026-11-03 起草）。本文件不是已授權的實作規格；使用者確認後，各 Phase 開工時再把定案內容寫進 `UX_FLOW.md`、`UI_SYSTEM.md`、`ARCHITECTURE.md` 與 `CHROME_ACCEPTANCE.md`，並把本文件對應段落標為已完成。
>
> 取代對象：Phase C 完成後，[`VISUAL_CONTENT_MODE_DESIGN.md`](VISUAL_CONTENT_MODE_DESIGN.md) 改為「已被取代」並指向新的現行規範。

## 0. 決策摘要

1. **現有圖文先拔除，再重新設計全站，最後放回新的圖文。** 目前私人資料夾內沒有圖文資料，因此拔除不需要資料遷移；但讀取端仍容忍舊欄位，避免未知的舊檔案讀壞。
2. **新圖文以一個外部遊記編輯台的操作為參考。** 參考的是互動模式（照片庫 → 段落、先選目標再放內容、拆篇／併回、平台版本），不是它的外觀或資料儲存方式。
3. **拔除時保留共用骨架。** `contentMode`、可發布項目（publishable view model）、作品庫與 Recovery 都維持「可以容納兩種內容」的寫法，Phase B 的全站設計針對「可發布項目」而不是「章節裡的一篇」。
4. **長文的切篇流程不改。** 全站調整只動作品庫、儲存狀態、發布與共用互動；Smart Split、讀稿／接縫與來源同步維持現行規範。

## 1. 從遊記編輯台學到的操作原則

這些原則是本提案所有設計的依據。後面每一項調整都會標註它依據哪一條。

| 編號 | 原則 | 遊記編輯台的做法 | StoryFlow 的對應 |
| --- | --- | --- | --- |
| L1 | **素材池 → 結構** | 當天照片全部在照片庫；寫作時把照片挑進段落，「沒用到的」一鍵篩出 | 長文已經是這個模式（來源章節是池，切出來的篇是結構；「尚未處理 N 字」就是「沒用到的」）。新圖文用同一個心智模型處理照片 |
| L2 | **先選目標，再放內容** | 點左邊段落 → 照片庫提示「點照片會加到第 3 段」→ 點照片就加入；也可直接拖曳 | 所有「把東西放進某處」的操作都先顯示目標，提示句說出放到哪裡 |
| L3 | **用量看得見** | 照片角落顯示「段 3」「IG2」「第 2 篇」；大圖檢視寫「用在第 3 段／還沒用到」 | 照片庫與文章圖片都顯示被哪裡引用 |
| L4 | **拆篇與併回** | 從某個小標「拆成新的一篇」；續篇可以「併回上一篇」，兩篇共用同一個照片庫 | 圖文項目可在小標處拆分、可併回上一則；長文早已有切篇，不新增 |
| L5 | **平台版本是一份結構化的衍生稿** | IG 模式：每則貼文有第一行、導言、短句行（每行配照片，編號自動算 `1 & 2.`）、結尾、📍地址、hashtag；上限 20 張；一鍵「複製貼文」 | 平台設定增加「內容形式」，輪播型平台有自己的版本編輯器，共用同一個照片庫 |
| L6 | **待補標記** | 正文寫 `【待補】`、`【待確認】`，頁首顯示「3 處待補／待確認」 | 兩種內容共用：工作台計數，發布時提醒 |
| L7 | **儲存狀態一句話** | 「儲存中⋯／有未儲存的修改／已儲存 14:32」；⌘S／Ctrl S 立即存；Esc 取消目前模式 | 全站統一同一句狀態與同一組快捷鍵 |
| L8 | **小刪除就地確認，大刪除走決策** | 刪段落、刪小標按鈕變成「再按一次確認」 | 項目內的結構編輯就地確認並可復原；刪項目、刪作品、刪圖檔仍是對話框 + Recovery |

刻意**不**採用的部分：

- 「儲存」按鈕：StoryFlow 維持自動儲存（`AGENTS.md`），只保留 ⌘S 作為「立刻寫入」的捷徑。
- 以天數為固定概念：「天」只是遊記的用法，StoryFlow 用通用的「作品 → 項目」，遊記的每一天就是一則項目。
- 雲端資料庫：資料仍只在使用者選擇的 StoryFlow 資料夾。
- 手機直接編輯：手機仍預設唯讀；照片挑選的手機底部面板（多選、依點選順序加入）保留為設計，只在解鎖編輯後可用。

## 4. Phase B：全站調整

### B1. 作品庫只做「選作品」

現況：每張作品卡有「開啟」「管理發布」「管理章節」「⋯」四個動作；「管理章節」在作品頁展開章節清單，與工作台左欄的章節清單是同一份內容的兩個管理處。

調整：

- 整張作品卡（標題區）就是「開啟」，進入該作品的工作台。
- 卡片右側只留「管理發布」與 `⋯`（改名、刪除）。
- 章節與項目的新增、編輯、刪除只在工作台左欄進行；作品頁不再展開章節清單。
- 作品卡的描述行維持現在的資訊：項目數、來源類型、最近編輯、發布進度。

依據：L2（一個地方做一件事）、UX_FLOW 的「相同標籤只有一個行為」。

### B2. 統一儲存狀態與快捷鍵

- 工作台標題列右側（長文與圖文同一位置）只顯示一句：`儲存中⋯`、`有未儲存的修改`、`已儲存 14:32`、`未能儲存，將重試`（警示色，可點開看原因）。
- ⌘S／Ctrl S：立即清空待寫入佇列；不是「另存」，沒有待寫入時只更新狀態句。
- Esc：取消目前的「放置模式」（例如 C 的「換照片」），沒有模式時才交給對話框關閉。
- 手機唯讀時沿用現行規則，隱藏儲存句。

依據：L7。

### B3. 待補標記 `【待補】`、`【待確認】`

- 任何內文（長文篇、圖文段落、後記）出現 `【待補` 或 `【待確認` 開頭的標記即計數。
- 工作台：目前項目的標題列顯示「2 處待補／待確認」，點一下跳到下一處。
- 發布：清單列顯示同一個計數；「標註已發布」與「保存發布紀錄」在有標記時多一步確認（不是禁止）。
- 搜尋：增加「只找待補」篩選。
- 複製內容不自動移除標記，讓使用者自己決定。

依據：L6。

### B4. 共用圖片挑選元件

把「照片庫 + 目標提示 + 大圖檢視」做成一個共用元件，長文的「文章圖片」與 C 的圖文都用它：

- 格狀縮圖，篩選：`全部`、`沒用到的`、`已用`（以及 C 的平台版本篩選）。
- 角落標示用量（L3）：長文顯示「正文前／正文後／後記後」，圖文顯示「段 3」「第 2 則」「IG 2」。
- 大圖檢視：← → 切換、說明行「#12 14:05 用在第 3 段／還沒用到」、主要動作「加到目前位置」。
- 支援拖曳到目標，也支援先點目標再點照片。

長文「文章圖片」因此從「三組清單 + 上移下移」改為「左邊三個位置、右邊照片庫」，資料模型（`placement`、`order`）不變。

依據：L1、L2、L3。

### B5. 平台「內容形式」

設定 → 發布平台的每個平台增加一個欄位：

| 內容形式 | 說明 | 預設適用 |
| --- | --- | --- |
| 全文 | 現行：標題、正文、圖片位置以 `〔圖 3〕` 標記，另列上傳順序 | 巴哈姆特、方格子與既有平台 |
| 輪播貼文 | 一則或多則貼文，每則：第一行、導言、短句行（每行配照片、自動編號）、結尾、地點、Hashtags；可設定每則照片上限（預設 20） | 使用者自行新增的 IG 類平台 |

- 既有平台與既有 workspace 一律視為「全文」，不跳遷移提示。
- 長文作品只會遇到「全文」；輪播貼文的版本編輯只在圖文項目出現（見 C4）。
- 平台改名與刪除沿用現行 Recovery-first 規則，平台版本隨平台搬移或移除。

依據：L5。

### B6. 項目內的結構編輯：就地確認 + 復原

把 UI_SYSTEM 的破壞性操作規則分成兩級：

| 等級 | 例子 | 互動 |
| --- | --- | --- |
| 結構編輯（項目內） | 刪一段、刪一個小標、從段落移除照片、移除一行輪播短句 | 按鈕文字變成「再按一次確認」（2.5 秒內），完成後出現「已刪除 · 復原」提示 10 秒；走一般自動儲存 |
| 資料刪除 | 刪項目、刪作品、從照片庫刪檔、併回上一則 | 對話框確認 → Recovery 快照 → 失敗即停止 → 寫入完成才回報 |

依據：L8、`AGENTS.md`「Destructive actions remain explicit, confirmed and Recovery-backed」。

### B7. 發布頁對齊兩種內容

- 發布清單恢復（Phase A 拿掉的）類型篩選與標籤，但只在作品庫真的同時有兩種作品時顯示。
- 「管理發布」燈箱：選到「輪播貼文」平台時，左欄顯示該平台版本的預覽與「複製貼文」，並提供「編輯此平台版本」連到工作台（C4）。
- 列上的摘要增加「圖片 N 張 · 待補 N」。

## 5. Phase C：新圖文

### C1. 名詞

| 名詞 | 意思 | 遊記的對應 |
| --- | --- | --- |
| 圖文作品 | 一個主題或一系列內容，擁有一個照片庫 | 「2023 北海道 10 日行」 |
| 圖文項目 | 一篇可發布的內容；單篇圖文就是只有一則項目的作品 | 某一天（或拆出來的續篇） |
| 小標 | 項目內的分段標題，可留空（開頭） | 小標 |
| 段落 | 一段文字加上它的照片 | 段落 |
| 照片庫 | 作品內所有匯入的照片 | 當天照片 |
| 平台版本 | 某個「輪播貼文」平台專用的結構化衍生稿 | IG 貼文 |

建立流程：`新增作品 → 長文／圖文 → 圖文：作品名稱 + 第一則標題 → 確認`。不再有「建立空系列」的選擇；取消不寫入任何東西（沿用現行交易規則）。

### C2. 資料模型

```text
project (contentMode: 'visual')
├─ photos[]                       ← 作品層級的照片庫
│  └─ { id, no, storedName, relativePath, mimeType, bytes, width, height,
│       takenAt, alt, caption, importedAt }
└─ visualEntries[]
   └─ { id, title, date, note, createdAt, updatedAt,
        sections[]: { id, heading,
                      blocks[]: { id, text, photoIds[] } },
        coverPhotoId,
        summary, hashtags, afterword, includeAfterword,          ← 沿用發布輔助欄位
        platformTitles, platformHashtags, platformIncludeAfterword,
        platformStatus, publicationRecords,                       ← 沿用
        platformVersions: { [platform]: { kind: 'carousel',
          posts[]: { id, headline, intro, outro, place, tags,
                     lines[]: { id, text, photoIds[] } } } } }
```

規則：

- `photo.no` 是作品內固定的照片編號（`#12`），匯入時遞增，刪除不回收；畫面與輸出都用它溝通。
- `takenAt`：JPEG 讀 EXIF `DateTimeOriginal`，讀不到用檔案的 `lastModified`；照片庫預設依它排序。
- 段落與平台版本只存 `photoIds`，同一張照片可以出現在多處；「沒用到的」= 沒有任何正文段落引用（平台版本另有自己的篩選）。
- 刪除項目不刪照片（照片屬於作品）；從照片庫刪照片是資料刪除（B6），刪除前列出引用它的段落並複製到 `Recovery/Assets`。
- 正規化容忍舊格式：只有 `body` 的項目轉成一個無小標、一段的 section；舊的 `images` 轉入作品照片庫並掛到該段。
- workspace schema 維持 version 2；新欄位都在 project 內部。

檔案位置：

```text
Works/<作品>/Photos/<storedName>              ← 照片庫
Works/<作品>/Visual/<entryId>/content.md       ← 項目匯出：小標、段落、相對路徑圖片
Works/<作品>/Visual/<entryId>/metadata.json
```

### C3. 圖文工作台

```text
┌ 作品與圖文 ───────┐┌ 項目編輯 ─────────────────────────┐┌ 照片庫 ──────────────┐
│ 切換作品 ▾        ││ 2023-07-14 · 已儲存 14:32 · 2 處待補 ││ 用了 18 / 64 張      │
│ 圖文清單 10 則    ││ [Day 4 湯倉神社          ]          ││ 全部 沒用到的 已用    │
│ ▸ Day 1 抵達      ││ [正文｜IG ▾]                        ││ 點照片會加到第 3 段   │
│ ▸ Day 4 湯倉神社  ││                                     ││ ┌──┐┌──┐┌──┐┌──┐    │
│   Day 4（續）     ││ ── 小標：早上 ── ↑ ↓ 拆成新的一則 ⋯ ││ │12││13││14││15│    │
│ ＋ 新增圖文       ││ ┌ 第 3 段文字…………………        ┐   ││ └──┘└──┘└──┘└──┘    │
│                   ││ │ [#12][#13] ◀ 換 ✕ ▶           │   ││ 段3  段3             │
│                   ││ └ 第 3 段 · 2 張  ↑ ↓ 下面加一段 ⋯┘   ││ 匯入照片            │
└───────────────────┘└─────────────────────────────────────┘└──────────────────────┘
```

- **桌面三欄**：左欄沿用 SOURCE 欄寬契約；照片庫在右，寬度 320–380 px；中間編輯區拿剩下的寬度。1366 px 以下左欄收合成「切換作品／圖文」下拉，照片庫維持可見；更窄時照片庫變成可收起的側抽屜。不得產生水平捲動。
- **選段落**：點段落或讓它的文字框取得焦點，該段即為目前目標，照片庫提示句同步改為「點照片會加到第 N 段」。
- **加照片**：點照片 → 加到目前段落；或拖到任何段落。已在該段的照片不重複加入，提示「#12 已經在這段了」；用在其他則時提示「#12 已加入，但它也用在第 2 則」。
- **段落內照片**：◀ ▶ 調順序、「換」進入替換模式（照片庫頂端顯示「選一張照片，取代 #12」，Esc 取消）、✕ 移除（B6 結構編輯）。
- **段落與小標**：↑ ↓ 移動、「下面加一段」、「在下面加一個小標」；刪除走 `⋯` 並就地確認。
- **大圖檢視**：在照片庫雙擊或點段落中的縮圖；← → 切換、說明行顯示用量、主要動作「加到第 N 段」或「用這張取代」。替代文字與圖說在大圖檢視下方編輯。
- **封面**：大圖檢視中「設為封面」；沒設定時發布用第一段的第一張。
- **自動儲存**：文字停止輸入後延遲寫入，照片引用變更立即寫入；切換項目、作品或頁面前清空佇列（沿用現行規則）。

### C4. 平台版本（輪播貼文）

- 編輯區標題下的切換 `[正文｜IG ▾]` 列出所有「輪播貼文」平台；沒有這類平台時不顯示切換。
- 切到平台版本時，照片庫保持在右側，多一個篩選「此平台已用」，計數改為「IG 用了 12 / 64 張」。
- 第一次開啟時提供「從正文產生」：每個小標成為一則貼文，每段成為一行並帶入該段照片。之後兩份各自獨立，正文修改不自動同步到平台版本。
- 每則貼文：第一行、導言、短句行、結尾、地點（輸出時前面加 📍）、Hashtags（預設帶入項目 Hashtags）。
- 短句行的編號依照片數自動算：一張 `3.`、兩張 `3 & 4.`、三張以上 `3–5.`；超過平台上限時計數變成警示色「22 / 20 張（超過了）」。
- 「複製貼文」在發布頁該平台的預覽中提供（B7），工作台不放發布捷徑（沿用現行規則）。

### C5. 拆成新的一則、併回上一則

- **拆分**：在第 2 個以後的小標 `⋯ → 從這裡拆成新的一則`。這個小標以後的內容移到新項目，標題為「原標題（續）」，插在原項目之後，兩則記錄同一個 `seriesOf`（原項目 id）。
- **併回**：續篇的 `⋯ → 併回上一則`。內容接到上一則最後，續篇刪除。
- 兩者都會改變項目數量，因此屬於資料刪除等級：確認對話框 → Recovery 快照（兩則都備份）→ 寫入 → 成功才更新清單。
- 發布狀態：拆出的新項目從「尚未發布」開始；併回時若續篇已有發布紀錄，對話框列出這些紀錄並提示「併回後只保留上一則的紀錄」。

### C6. 發布輸出

- **全文平台**：依小標與段落輸出文字，照片位置插入 `〔圖 #12〕`，並附「上傳順序：#12、#13、#20⋯」；Markdown 匯出寫入相對路徑圖片。
- **輪播貼文平台**：輸出該平台版本的純文字貼文，附照片順序清單。
- 完整度：標題 + 至少一段文字或一張照片（沿用現行規則）；待補標記依 B3 提醒。

### C7. 搜尋與手機

- 搜尋涵蓋項目標題、小標；勾選「同時搜尋正文」時涵蓋段落文字與平台版本短句。
- 手機唯讀：可瀏覽項目、照片庫與大圖檢視；所有加入、移動、替換、拆分、併回都受唯讀保護。解鎖編輯後，照片庫改為底部面板：先選段落，按「＋加照片」打開面板，可依點選順序多選，按「加入 N 張」完成。

## 6. 安全與測試對照

| 操作 | Recovery | 失敗時 | 瀏覽器測試至少涵蓋 |
| --- | --- | --- | --- |
| 刪除圖文項目 | 項目 metadata + content | 停止，不刪 | Recovery 失敗中止、照片保留 |
| 從照片庫刪照片 | `Recovery/Assets` 複本 | 停止，不刪 | 引用清單、失敗中止 |
| 拆分／併回 | 兩則項目都備份 | 停止，清單不變 | 中途寫入失敗的回滾 |
| 平台改名／刪除 | 沿用現行 | 沿用現行 | 平台版本跟著搬移或移除 |
| 段落、小標、照片引用的結構編輯 | 不建立（屬例行編輯） | 儲存句顯示失敗並重試 | 復原提示可還原 |

## 7. 待使用者確認

1. 照片庫放在**作品層級**（同一作品的所有項目共用，拆出來的續篇也共用），還是**項目層級**（每則各自一個照片庫）？本提案建議作品層級，因為遊記的續篇需要共用照片。
2. 「輪播貼文」平台版本是否需要？若只發全文平台，C4 可以延後，B5 也只需保留欄位不做 UI。
3. B1 把作品頁的「管理章節」拿掉，章節管理只在工作台：可以接受嗎？
4. 照片拍攝時間：讀 EXIF 需要一個小型 JPEG 解析器（不引入外部套件）；若不需要依拍攝時間排序，可以只用匯入順序。
