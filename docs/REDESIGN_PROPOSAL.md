# StoryFlow 全站調整與圖文重新設計提案

> 狀態：候選／待驗證（2026-11-03 起草，同日依使用者回饋改為「一圖一文」）。本文件不是已授權的實作規格；各 Phase 開工時再把定案內容寫進 `UX_FLOW.md`、`UI_SYSTEM.md`、`ARCHITECTURE.md` 與 `CHROME_ACCEPTANCE.md`，並把本文件對應段落標為已完成。
>
> 取代對象：Phase C 完成後，[`VISUAL_CONTENT_MODE_DESIGN.md`](VISUAL_CONTENT_MODE_DESIGN.md) 改為「已被取代」並指向新的現行規範。

## 0. 決策摘要

1. **現有圖文先拔除，再調整全站，最後放回新的圖文。** 私人資料夾內目前沒有圖文資料，拔除不需要資料遷移；讀取端仍容忍舊欄位，避免未知的舊檔案被讀壞。
2. **新圖文是「一圖一文」。** 一則圖文 = 標題、選填引言、一張圖片與圖說、正文。版面以使用者提供的平台文章畫面為參考：引言置中、圖片滿版、圖說置中在圖下、正文接在後面。
3. **照片來自 Google Drive 或 Dropbox。** 選取後複製進 StoryFlow 資料夾並記住來源；StoryFlow 不修改、不刪除雲端上的原檔。
4. **編輯時即時預覽。** 編輯欄與預覽欄並排，打字時預覽同步更新。
5. **參考外部遊記編輯台的操作模式**：照片庫、「沒用到的」篩選、用量標示、大圖檢視中直接選用。只參考互動，不參考外觀或資料儲存方式。
6. **拔除時保留共用骨架。** `contentMode`、可發布項目（publishable view model）、作品庫與 Recovery 維持能容納兩種內容的寫法。
7. **長文的切篇流程不改。** 全站調整只動作品庫、儲存狀態、待補標記、圖片元件與發布；Smart Split、讀稿／接縫、來源同步維持現行規範。

## 1. 參考的操作原則

| 編號 | 原則 | 參考來源的做法 | StoryFlow 的對應 |
| --- | --- | --- | --- |
| L1 | **素材池 → 內容** | 照片都在照片庫，寫作時挑出來用；「沒用到的」一鍵篩出 | 圖文作品有照片庫；每則圖文從中選一張。長文已是同一模式（來源章節是池，「尚未處理 N 字」就是沒用到的部分） |
| L2 | **先選目標，再放內容** | 提示句說出「點照片會加到第 3 段」 | 照片庫提示「點照片會設為《目前圖文》的圖片」；長文文章圖片提示要放到哪個位置 |
| L3 | **用量看得見** | 照片角落標示用在哪裡；大圖檢視寫「用在第 3 段／還沒用到」 | 照片角落顯示用在哪一則圖文 |
| L4 | **待補標記** | 正文寫 `【待補】`、`【待確認】`，頁首計數 | 兩種內容共用：工作台計數、發布前提醒 |
| L5 | **儲存狀態一句話** | 「儲存中⋯／有未儲存的修改／已儲存 14:32」；⌘S 立即存；Esc 取消目前模式 | 全站統一的狀態句與快捷鍵 |
| L6 | **小修改就地確認** | 刪除按鈕變成「再按一次確認」 | 項目內的小修改就地確認並可復原；刪項目、刪作品、刪圖檔仍走對話框與 Recovery |

刻意**不**採用：IG 等平台專用的貼文編輯介面（圖文只有一份內容，平台差異只在預覽與複製時套用格式）、儲存按鈕（StoryFlow 維持自動儲存）、雲端資料庫（資料只在 StoryFlow 資料夾）、手機直接編輯（手機維持預設唯讀）。

## 4. Phase B：全站調整

### B1. 作品庫只負責選作品

現況：每張作品卡有「開啟」「管理發布」「管理章節」「⋯」四個動作；「管理章節」在作品頁展開的章節清單，與工作台左欄的章節清單是同一份內容的兩個管理處。

調整：

- 點作品卡的標題區就是開啟，進入該作品的工作台。
- 卡片右側只留「管理發布」與 `⋯`（改名、刪除）。
- 章節與圖文的新增、編輯、刪除只在工作台左欄進行。
- 卡片描述行維持現有資訊：項目數、來源類型、最近編輯、發布進度。

### B2. 統一儲存狀態與快捷鍵

- 工作台標題列右側（長文與圖文同一位置）只顯示一句：`儲存中⋯`、`有未儲存的修改`、`已儲存 14:32`、`未能儲存，將重試`（警示色，可點開看原因）。
- ⌘S／Ctrl S 立即寫入待寫入佇列；沒有待寫入時只更新狀態句。
- Esc 取消目前的選取模式（例如 C4 的「換一張」），沒有模式時才交給對話框關閉。
- 手機唯讀時沿用現行規則，隱藏儲存句。

### B3. 待補標記 `【待補】`、`【待確認】`

- 任何內文（長文篇、圖文引言、圖說、正文、後記）出現以 `【待補` 或 `【待確認` 開頭的標記即計數。
- 工作台：目前項目的標題列顯示「2 處待補／待確認」，點一下跳到下一處。
- 發布：清單列顯示同一個計數；有標記時，「標註已發布」與「保存發布紀錄」多一步確認（提醒，不禁止）。
- 搜尋：增加「只找待補」篩選。
- 複製內容時不自動移除標記。

### B4. 共用照片庫元件

「照片庫 + 目標提示 + 大圖檢視」做成一個共用元件，給 C 的圖文與長文的「文章圖片」使用：

- 格狀縮圖，篩選 `全部`、`沒用到的`、`已用`。
- 角落標示用量：圖文顯示「用在《函館夜景》」，長文顯示「正文前／正文後／後記後」。
- 大圖檢視：← → 切換；說明行例如「IMG_0412 · 2023-07-14 20:05 · 還沒用到」；主要動作依情境為「用這張」或「加到正文前」。
- 支援拖曳到目標，也可以先選目標再點照片。

長文的「文章圖片」因此從「三組清單 + 上移下移」改為「左邊三個位置、右邊照片庫」，資料模型（`placement`、`order`）不變。

### B5. 項目內修改：就地確認 + 復原

| 等級 | 例子 | 互動 |
| --- | --- | --- |
| 項目內修改 | 清空引言、移除圖片（照片仍在照片庫）、移除長文的一張文章圖片引用 | 按鈕文字變成「再按一次確認」（2.5 秒內），完成後顯示「已移除 · 復原」10 秒，走一般自動儲存 |
| 資料刪除 | 刪圖文、刪作品、從照片庫刪檔案 | 對話框確認 → Recovery 快照 → 失敗即停止 → 寫入完成才回報 |

### B6. 發布頁對齊兩種內容

- 發布清單恢復類型篩選與標籤，但只在作品庫同時有兩種作品時顯示。
- 列上的摘要增加「圖片 1 張 · 待補 N」。

## 5. Phase C：新圖文（一圖一文）

### C1. 名詞

| 名詞 | 意思 |
| --- | --- |
| 圖文作品 | 一個主題或系列（例如一趟旅行、一個專欄），擁有一個照片庫 |
| 圖文 | 一篇可發布的「一圖一文」；只寫一篇也可以，就是只有一則圖文的作品 |
| 照片庫 | 這個作品從 Drive、Dropbox 或本機選進來的照片 |
| 照片來源 | 照片原本所在的雲端檔案；只用來追溯與重新抓取，不會被修改 |

建立流程：`新增作品 → 長文／圖文 → 圖文：作品名稱 + 第一則標題 → 確認`。不再提供「建立空系列」；取消不寫入任何東西（沿用現行交易規則）。

### C2. 一則圖文的結構與版面

依使用者提供的平台文章畫面：

```text
標題
  ❝
  引言（選填，置中、較淡）
[ 圖片（滿版） ]
  圖說（選填，置中、小字）
正文（首行縮排依平台格式設定）
後記（選填，沿用現行規則）
```

- 圖片可以留空：沒有圖片時，這則就是純文字圖文，仍可發布。
- 引言預設空白；「從正文第一句帶入」是一個按鈕，不自動帶入。
- 摘要、Hashtags、後記仍是發布輔助欄位，在「發布」編輯，不放進圖文編輯器（沿用 `AGENTS.md`）。

### C3. 照片來源：Google Drive、Dropbox、本機

照片庫的「匯入照片」選單有三個來源，選進來後都**複製**到 StoryFlow 資料夾：

| 來源 | 做法 | 需要的設定 |
| --- | --- | --- |
| Google Drive | Google Picker 選圖片（可多選），以 Drive API 下載內容 | 沿用現有的 Client ID、Picker API key 與 `drive.file` 權限；不新增權限範圍 |
| Dropbox | Dropbox Chooser 選圖片（可多選），以 Chooser 提供的直接連結下載 | 新增選填的 Dropbox App key，與 Google 設定一樣只存在 `settings.json` 與本機 |
| 本機／同步資料夾 | 系統檔案選擇器；Drive 或 Dropbox 桌面版的同步資料夾也從這裡選 | 不需要設定 |

規則：

- 複製而不是連結：照片要能離線預覽、在手機唯讀時從 StoryFlow 資料夾讀取，也不能因為雲端分享設定改變就消失。
- 每張照片記錄 `source`：`{ provider: 'drive' | 'dropbox' | 'local', id, name, url?, modifiedAt? }`。照片的 `⋯` 提供「重新從來源抓取」，覆蓋前先把舊檔複製到 `Recovery/Assets`。
- StoryFlow 絕不修改、移動或刪除 Drive 與 Dropbox 上的原檔（與 Google Docs 來源同一條規則）。
- 支援格式沿用文章圖片的 JPEG、PNG、WebP、GIF；HEIC 不支援，並提示「請先轉成 JPEG」。超過 8 MB 照樣匯入，但顯示警告。
- 拍攝時間：JPEG 讀取 EXIF `DateTimeOriginal`（自寫小型解析器，不引入套件），讀不到就用來源的修改時間；照片庫預設依拍攝時間排序。
- 沒有設定 Dropbox App key 時，選單中的 Dropbox 顯示為停用，旁邊寫「需要先在設定填入 Dropbox App key」（沿用「停用控制項要在旁邊寫原因」規則）。

### C4. 圖文工作台：編輯與即時預覽

```text
┌ 作品與圖文 ─────┐┌ 編輯 ────────────────────┐┌ 預覽  [手機寬｜桌面寬] ┐
│ 切換作品 ▾      ││ 已儲存 14:32 · 1 處待補  ││                        │
│ 圖文清單 12 則  ││ 標題 [函館夜景        ]  ││   函館夜景             │
│ ▸ 函館夜景      ││ 引言 [是否有什麼事情…  ]  ││        ❝               │
│   湯倉神社      ││ 圖片 ┌────┐ 換一張 ✕     ││  是否有什麼事情⋯       │
│   五稜郭        ││      │ 🖼 │ 用在：本則   ││  ┌──────────────┐      │
│ ＋ 新增圖文     ││      └────┘              ││  │     圖片     │      │
│                 ││ 圖說 [2010 年攝於東京 ]   ││  └──────────────┘      │
│ 照片庫 ▾        ││ 正文 ┌────────────────┐  ││    2010 年攝於東京     │
│  全部 沒用到的  ││      │ F，太遲太早⋯   │  ││  F，太遲太早或許都⋯    │
│  ▢▢▢▢          ││      └────────────────┘  ││                        │
└─────────────────┘└──────────────────────────┘└────────────────────────┘
```

- **三欄**：左欄沿用 SOURCE 欄寬契約，上半是圖文清單，下半是可收合的照片庫；中間是編輯欄；右邊是預覽欄。
- **即時預覽**：每次輸入都立即重繪預覽（不等自動儲存）。預覽欄可切換「手機寬」（約 390 px，貼近使用者提供的畫面）與「桌面寬」；可選「依平台格式」，套用該平台的段落間距、首行縮排與標題樣式，與發布時的「預覽與複製」同一套輸出規則（`publishing-output.js`）。
- **選圖片**：點編輯欄的圖片框，或在照片庫點一張照片 → 設為目前圖文的圖片。照片已被另一則使用時提示「這張也用在《五稜郭》」，但仍允許（同一張照片可以出現在兩則）。
- **換一張**：進入選取模式，照片庫頂端顯示「選一張照片，取代目前圖片」，Esc 取消。
- **大圖檢視**：雙擊照片庫縮圖或點預覽中的圖片；← → 切換；主要動作「用這張」。替代文字在大圖檢視下方編輯。
- **寬度**：1366 px 以下，預覽欄改為編輯欄上方的「編輯｜預覽」切換；左欄收合成下拉。所有斷點都不得產生水平捲動。
- **自動儲存**：文字停止輸入後延遲寫入，圖片變更立即寫入；切換圖文、作品或頁面前清空佇列（沿用現行規則）。

### C5. 資料模型

```text
project (contentMode: 'visual')
├─ photos[]                        ← 作品層級的照片庫
│  └─ { id, storedName, relativePath, mimeType, bytes, width, height,
│       takenAt, alt, importedAt,
│       source: { provider, id, name, url, modifiedAt } }
└─ visualEntries[]
   └─ { id, title, quote, photoId, caption, body, createdAt, updatedAt,
        summary, hashtags, afterword, includeAfterword,           ← 沿用發布輔助欄位
        platformTitles, platformHashtags, platformIncludeAfterword,
        platformStatus, publicationRecords }                        ← 沿用
```

- 一則圖文只有一個 `photoId`（可為空）。圖說寫在圖文上，不寫在照片上：同一張照片在兩則中可以有不同圖說；替代文字描述照片內容，所以寫在照片上。
- 刪除圖文不刪照片（照片屬於作品）；從照片庫刪照片屬於資料刪除（B5），刪除前列出使用它的圖文，並複製到 `Recovery/Assets`。
- 正規化容忍舊格式：舊的 `images[]` 取第一張移入照片庫並設為 `photoId`，其餘照片也移入照片庫；舊的 `body` 原樣保留。
- workspace schema 維持 version 2；新欄位都放在 project 內部。

檔案位置：

```text
Works/<作品>/Photos/<storedName>             ← 照片庫
Works/<作品>/Visual/<entryId>/content.md      ← 匯出：標題、引言、圖片相對路徑、圖說、正文
Works/<作品>/Visual/<entryId>/metadata.json
```

### C6. 發布輸出

- **複製內容**：依平台格式輸出「引言 → 〔圖片〕→ 圖說 → 正文 → 後記」。純文字剪貼簿在圖片位置放 `〔圖片：函館夜景.jpg〕`；HTML 剪貼簿輸出引言區塊與圖說段落，圖片仍需使用者在平台上傳（StoryFlow 不自動發布）。
- 「預覽與複製」提供「下載圖片」，讓使用者把這張照片存出來再上傳到平台。
- 完整度：標題 + 正文或圖片（沿用現行規則）；待補標記依 B3 提醒。

### C7. 搜尋與手機

- 搜尋涵蓋圖文標題與照片檔名；勾選「同時搜尋正文」時涵蓋引言、圖說與正文。
- 手機唯讀：可瀏覽圖文、預覽（預設手機寬）與照片庫；匯入、選圖、編輯都受唯讀保護。

## 6. 安全與測試對照

| 操作 | Recovery | 失敗時 | 瀏覽器測試至少涵蓋 |
| --- | --- | --- | --- |
| 刪除圖文 | 圖文 metadata + content | 停止，不刪 | Recovery 失敗中止、照片保留在照片庫 |
| 從照片庫刪照片 | `Recovery/Assets` 複本 | 停止，不刪 | 使用中的圖文清單、失敗中止 |
| 重新從來源抓取 | 舊檔複製到 `Recovery/Assets` | 停止，保留舊檔 | 下載失敗不覆蓋 |
| 雲端匯入 | 不需要（只新增檔案） | 該張標示失敗，其他照片繼續匯入 | Drive／Dropbox 下載失敗、重複檔名改為加編號 |
| 項目內修改 | 不建立（屬例行編輯） | 儲存句顯示失敗並重試 | 「復原」可還原 |

Drive 與 Dropbox 的瀏覽器測試以 stub 取代真實 API，不使用真實憑證或私人照片（`AGENTS.md`）。
