> 狀態：已完成設計紀錄（2026-11-03 起草並完成 Phase 0、A、B、C）。現行規範已寫入 `UX_FLOW.md`（〈Visual works: one image per article〉、〈Pending marks and the save shortcut〉）、`UI_SYSTEM.md`、`ARCHITECTURE.md` 與 `CHROME_ACCEPTANCE.md`；本文件保留決策與分期紀錄。
>
> 取代對象：[`VISUAL_CONTENT_MODE_DESIGN.md`](VISUAL_CONTENT_MODE_DESIGN.md) 已改為「已被取代」並指向現行規範。

## 0. 決策摘要

1. **現有圖文先拔除，再調整全站，最後放回新的圖文。** 私人資料夾內目前沒有圖文資料，拔除不需要資料遷移；讀取端仍容忍舊欄位，避免未知的舊檔案被讀壞。
2. **新圖文是「一圖一文」。** 一則圖文 = 標題、選填引言、一張圖片與圖說、正文。版面以使用者提供的平台文章畫面為參考：引言置中、圖片滿版、圖說置中在圖下、正文接在後面。
3. **照片留在 Google Drive，StoryFlow 只記住引用。** 照片不複製進 StoryFlow 資料夾；StoryFlow 只保存 Drive 檔案 ID 與顯示需要的資訊，預覽時才向 Drive 讀取。StoryFlow 不修改、不移動、不刪除 Drive 上的照片。不支援 Dropbox。
4. **同一作品的圖文共用一個照片庫。** 「沒用到的」篩選因此能看出還有哪些照片沒寫。
5. **編輯時即時預覽。** 編輯欄與預覽欄並排，打字時預覽同步更新。
6. **不做 IG 等平台專用的貼文編輯介面。** 圖文只有一份內容，平台差異只在預覽與複製時套用格式。
7. **作品頁不再管理章節。** 章節與圖文的管理只在工作台左欄（B1）。
8. **參考外部遊記編輯台的操作模式**：照片庫、「沒用到的」篩選、用量標示、大圖檢視中直接選用。只參考互動，不參考外觀或資料儲存方式。
9. **拔除時保留共用骨架。** `contentMode`、可發布項目（publishable view model）、作品庫與 Recovery 維持能容納兩種內容的寫法。
10. **長文的切篇流程不改。** 全站調整只動作品庫、儲存狀態、待補標記、照片元件與發布；Smart Split、讀稿／接縫、來源同步維持現行規範。

## 1. 參考的操作原則

| 編號 | 原則 | 參考來源的做法 | StoryFlow 的對應 |
| --- | --- | --- | --- |
| L1 | **素材池 → 內容** | 照片都在照片庫，寫作時挑出來用；「沒用到的」一鍵篩出 | 圖文作品有照片庫；每則圖文從中選一張。長文已是同一模式（來源章節是池，「尚未處理 N 字」就是沒用到的部分） |
| L2 | **先選目標，再放內容** | 提示句說出「點照片會加到第 3 段」 | 照片庫提示「點照片會設為《目前圖文》的圖片」；長文文章圖片提示要放到哪個位置 |
| L3 | **用量看得見** | 照片角落標示用在哪裡；大圖檢視寫「用在第 3 段／還沒用到」 | 照片角落顯示用在哪一則圖文 |
| L4 | **待補標記** | 正文寫 `【待補】`、`【待確認】`，頁首計數 | 兩種內容共用：工作台計數、發布前提醒 |
| L5 | **儲存狀態一句話** | 「儲存中⋯／有未儲存的修改／已儲存 14:32」；⌘S 立即存；Esc 取消目前模式 | 全站統一的狀態句與快捷鍵 |
| L6 | **小修改就地確認** | 刪除按鈕變成「再按一次確認」 | 項目內的小修改就地確認並可復原；刪項目、刪作品仍走對話框與 Recovery |

刻意**不**採用：IG 等平台專用的貼文編輯介面、儲存按鈕（StoryFlow 維持自動儲存）、雲端資料庫（StoryFlow 的資料只在 StoryFlow 資料夾）、手機直接編輯（手機維持預設唯讀）。

### B1. 作品庫只負責選作品（已確認）

現況：每張作品卡有「開啟」「管理發布」「管理章節」「⋯」四個動作；「管理章節」在作品頁展開的章節清單，與工作台左欄的章節清單是同一份內容的兩個管理處。

調整：

- 點作品卡的標題區就是開啟，進入該作品的工作台。
- 卡片右側只留「管理發布」與 `⋯`（改名、刪除）。
- 章節與圖文的新增、編輯、刪除只在工作台左欄進行；作品頁不再展開章節清單。
- 卡片描述行維持現有資訊：項目數、來源類型、最近編輯、發布進度。

### B2. 統一儲存狀態與快捷鍵

- 工作台標題列右側（長文與圖文同一位置）只顯示一句：`儲存中⋯`、`有未儲存的修改`、`已儲存 14:32`、`未能儲存，將重試`（警示色，可點開看原因）。
- ⌘S／Ctrl S 立即寫入待寫入佇列；沒有待寫入時只更新狀態句。
- Esc 取消目前的選取模式（例如 C4 的「換一張」），沒有模式時才交給對話框關閉。
- 手機唯讀時沿用現行規則，隱藏儲存句。

### B3. 待補標記 `【待補】`、`【待確認】`

- 任何內文（長文篇、圖文引言、圖說、正文、後記）出現以 `【待補` 或 `【待確認` 開頭的標記即計數。
- 工作台：目前項目的標題列顯示「2 處待補／待確認」，點一下跳到下一處。
- 發布：清單列顯示同一個計數；有標記時，「標註已發布」與「保存發布紀錄」多一步確認（提醒，不禁止）。
- 搜尋：增加「只找待補」篩選。
- 複製內容時不自動移除標記。

### B4. 共用照片庫元件

「照片庫 + 目標提示 + 大圖檢視」做成一個共用元件。它只負責顯示、篩選與選用，不負責照片存在哪裡，由呼叫端提供讀取方式：

- 格狀縮圖，篩選 `全部`、`沒用到的`、`已用`。
- 角落標示用量（例如「用在《函館夜景》」）。
- 大圖檢視：← → 切換；說明行例如「IMG_0412 · 2023-07-14 20:05 · 還沒用到」；主要動作「用這張」。
- 支援拖曳到目標，也可以先選目標再點照片。

C 的圖文以 Drive 為讀取來源使用它。長文「文章圖片」維持現狀，不改用這個元件（見 §7）。

### C1. 名詞

| 名詞 | 意思 |
| --- | --- |
| 圖文作品 | 一個主題或系列（例如一趟旅行、一個專欄），擁有一個照片庫 |
| 圖文 | 一篇可發布的「一圖一文」；只寫一篇也可以，就是只有一則圖文的作品 |
| 照片庫 | 這個作品從 Google Drive 選進來的照片**引用**清單；照片本身仍在 Drive |

建立流程：`新增作品 → 長文／圖文 → 圖文：作品名稱 + 第一則標題 → 確認`。不再提供「建立空系列」；取消不寫入任何東西（沿用現行交易規則）。

### C2. 一則圖文的結構與版面

依使用者提供的平台文章畫面：

```text
標題
  ❝
  引言（選填，置中、較淡）
[ 圖片（滿版） ]
  圖說（選填，置中、小字）
正文（首行縮排依平台格式設定）
後記（選填，沿用現行規則）
```

- 圖片可以留空：沒有圖片時，這則就是純文字圖文，仍可發布。
- 引言預設空白；「從正文第一句帶入」是一個按鈕，不自動帶入。
- 摘要、Hashtags、後記仍是發布輔助欄位，在「發布」編輯，不放進圖文編輯器（沿用 `AGENTS.md`）。

### C3. 照片來源：Google Drive 引用

- 照片庫的「從 Google Drive 加入照片」開啟 Google Picker，只列圖片，可以進資料夾、可以多選。
- 沿用現有的 Client ID、Picker API key 與 `drive.file` 權限，不新增權限範圍：使用者在 Picker 選過的檔案，StoryFlow 之後都能讀取，但讀不到其他沒選過的檔案。
- 加入後只在 `workspace.json` 記錄引用（C5），**不下載保存、不寫入 StoryFlow 資料夾**。
- 預覽時才向 Drive 讀取：縮圖用 Drive 提供的縮圖，大圖與預覽欄讀取原圖。讀到的圖片只放在這個分頁的記憶體（object URL），不寫入 localStorage、IndexedDB 或任何檔案；關閉分頁、切換作品或離開此裝置時釋放。
- 需要先登入 Google 才能看到照片。未登入時，照片位置顯示檔名與「登入 Google 後顯示照片」，文字編輯與預覽排版照常可用。
- Drive 上的檔案被刪除、移動到使用者無權存取的位置或取消分享時，照片顯示「Drive 上找不到這張照片」，提供「重新選擇」（換成另一張 Drive 照片）與「移出照片庫」。StoryFlow 不自動移除引用。
- StoryFlow 絕不修改、移動、改名或刪除 Drive 上的照片（與 Google Docs 來源同一條規則）。
- 支援格式：JPEG、PNG、WebP、GIF。Picker 只列這四種格式；HEIC 不會出現在清單中，照片庫的說明寫「HEIC 請先在 Drive 轉成 JPEG」。
- 拍攝時間：優先使用 Drive 檔案資訊中的 `imageMediaMetadata.time`，沒有時用 Drive 的建立時間；照片庫預設依拍攝時間排序。不需要自己解析 EXIF。
- 不支援 Dropbox，也不支援本機檔案：沒有複製就無法在下次開啟時找回本機檔案。
- **這是產品邊界的變更。** `AGENTS.md`〈Product boundaries〉與 `README.md` 目前寫「圖片只屬於使用者選擇的 StoryFlow 資料夾」。Phase C 的第一個 PR 要同時改寫這一條：StoryFlow 資料夾仍保存正文與 workspace；圖文照片留在使用者自己的 Google Drive，StoryFlow 只保存引用，不得把照片內容寫進 GitHub、StoryFlow 資料夾或瀏覽器儲存。

### C4. 圖文工作台：編輯與即時預覽

```text
┌ 作品與圖文 ─────┐┌ 編輯 ────────────────────┐┌ 預覽  [手機寬｜桌面寬] ┐
│ 切換作品 ▾      ││ 已儲存 14:32 · 1 處待補  ││                        │
│ 圖文清單 12 則  ││ 標題 [函館夜景        ]  ││   函館夜景             │
│ ▸ 函館夜景      ││ 引言 [是否有什麼事情…  ]  ││        ❝               │
│   湯倉神社      ││ 圖片 ┌────┐ 換一張 ✕     ││  是否有什麼事情⋯       │
│   五稜郭        ││      │ 🖼 │ 用在：本則   ││  ┌──────────────┐      │
│ ＋ 新增圖文     ││      └────┘              ││  │     圖片     │      │
│                 ││ 圖說 [2010 年攝於東京 ]   ││  └──────────────┘      │
│ 照片庫 ▾        ││ 正文 ┌────────────────┐  ││    2010 年攝於東京     │
│  全部 沒用到的  ││      │ F，太遲太早⋯   │  ││  F，太遲太早或許都⋯    │
│  ▢▢▢▢          ││      └────────────────┘  ││                        │
└─────────────────┘└──────────────────────────┘└────────────────────────┘
```

- **三欄**：左欄沿用 SOURCE 欄寬契約，上半是圖文清單，下半是可收合的照片庫；中間是編輯欄；右邊是預覽欄。
- **即時預覽**：每次輸入都立即重繪預覽（不等自動儲存）。預覽欄可切換「手機寬」（約 390 px，貼近使用者提供的畫面）與「桌面寬」；可選「依平台格式」，套用該平台的段落間距、首行縮排與標題樣式，與發布時的「預覽與複製」同一套輸出規則（`publishing-output.js`）。
- **選圖片**：點編輯欄的圖片框，或在照片庫點一張照片 → 設為目前圖文的圖片。照片已被另一則使用時提示「這張也用在《五稜郭》」，但仍允許（同一張照片可以出現在兩則）。
- **換一張**：進入選取模式，照片庫頂端顯示「選一張照片，取代目前圖片」，Esc 取消。
- **大圖檢視**：雙擊照片庫縮圖或點預覽中的圖片；← → 切換；主要動作「用這張」；另有「在 Google Drive 開啟」。替代文字在大圖檢視下方編輯。
- **寬度**：1366 px 以下，預覽欄改為編輯欄上方的「編輯｜預覽」切換；左欄收合成下拉。所有斷點都不得產生水平捲動。
- **自動儲存**：文字停止輸入後延遲寫入，圖片選擇立即寫入；切換圖文、作品或頁面前清空佇列（沿用現行規則）。

### C5. 資料模型

```text
project (contentMode: 'visual')
├─ photos[]                        ← 作品層級的照片庫（只有引用）
│  └─ { id, driveFileId, name, mimeType, width, height, takenAt,
│       alt, addedAt }
└─ visualEntries[]
   └─ { id, title, quote, photoId, caption, body, createdAt, updatedAt,
        summary, hashtags, afterword, includeAfterword,           ← 沿用發布輔助欄位
        platformTitles, platformHashtags, platformIncludeAfterword,
        platformStatus, publicationRecords }                        ← 沿用
```

- 一則圖文只有一個 `photoId`（可為空）。圖說寫在圖文上，不寫在照片上：同一張照片在兩則中可以有不同圖說；替代文字描述照片內容，所以寫在照片上。
- 不保存 Drive 的縮圖網址或下載網址：它們會過期，每次需要時重新向 Drive 取得。
- 照片庫只有引用，所以「移出照片庫」與刪除圖文都不會刪到任何照片檔案；使用中的照片被移出時，對應圖文的 `photoId` 清空，並出現「復原」（B5）。
- 正規化容忍舊格式：舊圖文的 `images[]`（StoryFlow 資料夾內的檔案）不轉換，原樣保留，該則顯示「舊版圖片，請從 Google Drive 重新選擇」；舊的 `body` 原樣保留。
- workspace schema 維持 version 2；新欄位都放在 project 內部。

檔案位置：

```text
Works/<作品>/Visual/<entryId>/content.md      ← 匯出：標題、引言、圖片的 Drive 連結、圖說、正文
Works/<作品>/Visual/<entryId>/metadata.json
```

### C6. 發布輸出

- **複製內容**：依平台格式輸出「引言 → 〔圖片〕→ 圖說 → 正文 → 後記」。純文字剪貼簿在圖片位置放 `〔圖片：IMG_0412.jpg〕`；HTML 剪貼簿輸出引言區塊與圖說段落。圖片仍需使用者在平台自行上傳（StoryFlow 不自動發布）。
- 「預覽與複製」提供「下載圖片」：從 Drive 讀取原圖，交給瀏覽器下載到使用者的裝置，方便上傳到平台；StoryFlow 不留副本。
- 完整度：標題 + 正文或圖片（沿用現行規則）；照片在 Drive 找不到時列為警告，不影響完整度；待補標記依 B3 提醒。

### C7. 搜尋與手機

- 搜尋涵蓋圖文標題與照片檔名；勾選「同時搜尋正文」時涵蓋引言、圖說與正文。
- 手機唯讀：可瀏覽圖文、預覽（預設手機寬）與照片庫（需要登入 Google，沿用 O-07 的「匯入 settings.json → 登入 Google → 連接資料夾」路線）；加入照片、選圖、編輯都受唯讀保護。

## 6. 安全與測試對照

| 操作 | Recovery | 失敗時 | 瀏覽器測試至少涵蓋 |
| --- | --- | --- | --- |
| 刪除圖文 | 圖文 metadata + content | 停止，不刪 | Recovery 失敗中止；照片庫引用不變 |
| 移出照片庫 | 不建立（只移除引用，可「復原」） | 儲存句顯示失敗並重試 | 使用中的圖文清空 `photoId` 後可復原 |
| 從 Drive 加入照片 | 不需要（只新增引用） | 該張不加入，其他照片照常加入 | Picker 取消不寫入；重複選同一個 Drive 檔案不重複加入 |
| Drive 讀取失敗 | 不適用 | 顯示「找不到這張照片」或「登入 Google 後顯示照片」，不移除引用 | 未登入、404、403 三種狀態 |
| 項目內修改 | 不建立（屬例行編輯） | 儲存句顯示失敗並重試 | 「復原」可還原 |

- Drive 的瀏覽器測試以 stub 取代 Picker 與 Drive API，不使用真實憑證或私人照片（`AGENTS.md`）。
- 靜態檢查新增一條：圖文的 Drive 照片不得經過 StoryFlow 資料夾寫入路徑，也不得寫入 localStorage 或 IndexedDB。

## 7. 已確認的決定

- 照片庫在作品層級，同一作品的圖文共用。
- 照片只引用 Google Drive，不複製進 StoryFlow 資料夾；不支援 Dropbox 與本機檔案。
- 作品頁不再管理章節。
- 圖文不做 IG 等平台專用的貼文編輯介面。
- 長文的「文章圖片」維持現狀：複製進 StoryFlow 資料夾，沿用現行的匯入、位置與 Recovery 規則；B4 的共用照片元件只用於圖文。
- 每個 Phase 一個 PR，依 0 → A → B → C 順序進行；每個 PR 跑完整 `npm test`，長文流程不得改壞。
