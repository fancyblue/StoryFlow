> 狀態：Phase 2 已完成；圖文維護與整合發布已開放
> 用途：記錄「圖文系列」的使用流程、資料邊界與分階段實作方向。Phase 1 提供建立與維護；Phase 2 已整合共用發布頁、發布紀錄與搜尋。

## 1. 設計結論

圖文維護繼續放在同一個 StoryFlow，但與長文切篇使用不同的工作台。

```text
StoryFlow
├─ 長文作品 → 長文工作台 → 章節來源 → Smart Split → 切篇確認 → 發布
└─ 圖文系列 → 圖文工作台 → 內容編排 → 預覽 → 發布
```

兩種模式共用：

- 作品庫、搜尋與導覽。
- StoryFlow 私人資料夾、儲存狀態與 Recovery。
- 圖片匯入、私人 assets 與圖片預覽。
- 平台設定、平台標題、複製與發布紀錄。
- 手機預設唯讀與連線安全規則。

兩種模式不共用主要編輯介面。圖文內容不出現 Smart Split、場景切點或「少／多一個場景」。

## 2. 目標與非目標

### 目標

1. 讓使用者可以用文字與多張圖片組成一則可發布的內容。
2. 支援封面、圖片順序、圖說與替代文字維護。
3. 沿用現有的私人檔案、發布平台與 Recovery 機制。
4. 保留長文工作台的專注度，不讓圖文功能干擾切篇流程。
5. 維持私人單人工具的輕量範圍。

### 第一階段非目標

- 圖片裁切、濾鏡、拼圖或繪圖。
- 自動將圖片上傳至社群或發布平台。
- 社群貼文排程、數據分析或多人協作。
- 雲端圖庫、CDN 或圖片 AI 處理。
- 自由拖曳版面畫布。第一版使用可預測的線性圖文順序。
- 同一作品同時混用長文與圖文工作台。如日後出現明確需求，再設計可審核的混合模式。

## 3. 內容類型在什麼時候選擇

### 建議決策：建立作品時選擇一次

使用者按下「建立第一個作品」或「＋ 新作品」後，第一個決策步驟就是選擇作品類型。

```text
建立作品
  ↓
選擇內容類型
  ├─ 長文作品
  │    ↓
  │  選擇 Google Docs／手動建立
  │    ↓
  │  預覽來源 → 確認建立
  │
  └─ 圖文系列
       ↓
     輸入系列名稱
       ↓
     選擇「建立空系列」或「同時新增第一則圖文」
       ↓
     確認建立
```

不在以下時機反覆詢問類型：

- 每次開啟網站。
- 每次切換作品。
- 進入發布頁。
- 新增作品內容時。

作品類型屬於作品結構，建立後導覽自動進入對應工作台。這能避免每次操作都先做一次模式選擇。

### 選擇的安全邊界

- 類型選擇在「建立作品交易」內進行。關閉、Escape 或取消都不建立空作品。
- 確認前可回上一步重選類型。
- 作品建立且已有內容後，不提供一鍵切換類型，避免章節、圖文項目與輸出檔案被誤解。
- 既有作品在載入時若沒有類型欄位，一律視為「長文作品」，不顯示遷移燈箱。

## 4. 全網站導覽與頁面變化

### 側邊導覽

維持現有四個主要位置：

- 工作台
- 作品
- 發布
- 設定

不另外增加「圖文」主導覽。「工作台」會依目前作品類型顯示長文或圖文工作台。

### 作品頁

每張作品卡增加一個安靜的類型標籤：

- `長文`
- `圖文`

操作層級依類型變化：

| 類型 | 主要管理動作 | 次要動作 |
| --- | --- | --- |
| 長文 | 管理章節 | 工作台、管理發布、`...` |
| 圖文 | 管理圖文 | 工作台、管理發布、`...` |

相同的動作在不同作品卡上維持相同尺寸與顏色。類型由標籤表達，不靠按鈕顏色猜測。

### 工作台

#### 長文工作台

現有流程保持不變：作品與章節、來源更新、Smart Split、切篇確認與發布進度。

#### 圖文工作台

採二欄桌面結構：

```text
左側：圖文清單                 右側：目前圖文編輯器
├─ 搜尋／狀態篩選             ├─ 標題
├─ 草稿、待發布、已完成        ├─ 正文
├─ 圖文項目清單               ├─ 圖片與封面
└─ ＋ 新增圖文                 ├─ 圖說／替代文字
                                ├─ 平台預覽
                                └─ 保存／前往發布
```

編輯器不使用自由畫布。第一版以「正文 + 有順序的圖片」為核心，並使用預覽表達最終閱讀順序。

### 發布頁

長文發布篇與圖文項目放在同一發布頁，共用作品與狀態篩選。

- 列表項顯示 `長文` 或 `圖文` 標籤。
- 「繼續發布」依最近確認／編輯且尚未完成的項目排序，不區分內容類型。
- 圖文項目沒有「預覽預設設定」的長文切篇語意，直接顯示「預覽／複製」與「管理發布」。
- 圖片仍需使用者依預覽順序逐張上傳至外部平台；StoryFlow 不自動發布圖檔。

## 6. 圖文工作台主要操作流程

### 新增圖文

```text
圖文工作台 → ＋ 新增圖文 → 輸入標題與正文
                                  ├─ 匯入圖片
                                  ├─ 設定封面
                                  ├─ 圖說／替代文字
                                  └─ 調整順序
                                             ↓
                                           預覽
                                             ↓
                                      保存草稿／前往發布
```

「保存草稿」是編輯階段主要動作。「前往發布」只在已成功保存且至少有標題與文字或圖片時出現。

### 編輯圖片資訊

```text
點選圖片 → 專注編輯燈箱
              ├─ 替代文字
              ├─ 圖說
              ├─ 設為封面
              ├─ 向前／向後移動
              └─ 移除
```

圖片設定不全部常駐在主編輯器，避免每張圖的表單擠壓文字與順序預覽。

### 前往發布

```text
圖文工作台 → 前往發布 → 對應項目自動展開
                                 ├─ 預覽／複製文字
                                 ├─ 依序上傳圖片
                                 ├─ 修改平台標題
                                 └─ 記錄發布
```

## 7. 資料模型方向

本節是實作方向，完成技術 spike 後才確定最終 schema。

### 作品

```js
{
  id: "stable-project-id",
  title: "系列名稱",
  contentMode: "longform" | "visual",
  chapters: [],       // longform 使用
  visualEntries: []   // visual 使用
}
```

- 既有資料缺少 `contentMode` 時正規化為 `longform`。
- 不把圖文假裝成章節或已切篇 `part`，避免之後的字段意義混淆。
- 共用發布頁透過 adapter 取得一致的 publishable view model，不強迫兩種來源共用同一個內部結構。

### 圖文項目

```js
{
  id: "stable-entry-id",
  title: "圖文內部名稱",
  body: "Markdown or normalized text",
  status: "draft" | "ready",
  coverImageId: "image-id-or-empty",
  images: [
    {
      id: "image-id",
      storedName: "...",
      relativePath: "...",
      mimeType: "image/jpeg",
      bytes: 0,
      width: 0,
      height: 0,
      alt: "",
      caption: "",
      order: 0
    }
  ],
  platformTitles: {},
  platformStatus: {},
  publicationRecords: {},
  createdAt: "ISO timestamp",
  updatedAt: "ISO timestamp"
}
```

`status` 只表示編輯準備狀態；平台是否已發布仍以 `platformStatus` 為準。不從圖片數量、文字長度或替代文字自動猜測「已完成」。

### 私人檔案結構（建議）

```text
StoryFlow/
└─ Works/
   └─ <作品>/
      ├─ ...現有長文章節
      └─ Visual/
         └─ <entry-id>/
            ├─ content.md
            ├─ metadata.json
            └─ assets/
               └─ *.{jpg,jpeg,png,webp,gif}
```

以固定 ID 作為資料夾身分，使改名不需移動圖片，也避免同名圖文衝突。`content.md` 可使用 front matter 或其他可讀標題，不把 ID 暴露成介面上的主要名稱。

## 8. 儲存、刪除與相容性

- 圖文存檔與 workspace 寫入走現有串行佇列，不由 UI 直接寫檔。
- 每個結構性寫入必須等到實際成功後才顯示「已保存」。
- 刪除圖文、替換資料與刪除圖檔前，沿用 `StoryFlowProjectPersistence.prepareRecovery()`。
- 刪除圖文時預設只刪除 workspace 關聯與輸出文字，圖檔保留。真正刪除圖檔需另一個帶 Recovery 的明確決策。
- Phase 0 保持外層 workspace schema version 2：新增欄位位於各作品 `state`，且缺少欄位可安全正規化，因此不需要為可選加法欄位強迫舊資料升版。若 Phase 1 改變外層 workspace 結構，再重新評估升版。
- 載入新版 workspace 時必須先正規化作品類型與圖文欄位，再進入渲染。

## 9. UI/UX 原則

1. **模式固定，任務清楚**：選過作品後，工作台不再顯示模式開關。
2. **編輯與發布分階段**：圖文工作台處理內容；發布頁處理平台差異與發布紀錄。
3. **主介面保持密度**：圖說、替代文字與刪除透過專注 action 編輯，不展開每張圖的完整表單。
4. **圖片不只有視覺狀態**：封面、缺少替代文字、檔案遺失都有文字標示。
5. **只有一個建議下一步**：草稿中以保存為主；保存完成才讓「前往發布」取得強調。
6. **不假裝自動上傳**：複製文字後明確提示圖片仍需逐張上傳。
7. **桌面 Chrome 優先**：桌面提供完整編輯；手機優先清單、預覽與唯讀。

## 10. 狀態與空畫面

| 狀態 | 主畫面 | 建議主動作 |
| --- | --- | --- |
| 圖文系列內沒有項目 | 說明圖文會儲存在私人資料夾 | 新增第一則圖文 |
| 有草稿但尚未選擇 | 圖文清單 + 閱讀式空狀態 | 開啟最近草稿 |
| 正在編輯 | 文字與圖片順序 | 保存草稿 |
| 儲存失敗 | 保留編輯內容並顯示錯誤 | 重試保存／處理 Recovery |
| 已儲存且可發布 | 完成摘要與預覽 | 前往發布 |
| 圖檔遺失 | 保留原順序的警示卡 | 重新連結／移除關聯 |

## 11. 實作分階段

### Phase 0：技術 spike，不開放使用

- [x] 確認 `contentMode` 正規化與既有 workspace 相容。
- [x] 確認圖文項目輸出路徑與圖片 adapter。
- [x] 確認共用發布頁不需改寫長文 `part` 結構。
- [x] 用 fixture 驗證新舊 workspace 可來回載入。

#### Phase 0 決策紀錄（2026-08-28）

- 缺少或不認得的 `contentMode` 一律正規化為 `longform`；只有明確的 `visual` 才進入圖文資料模型。
- 圖文作品可在沒有 `chapters` 的情況下成立，項目只存在 `visualEntries`；Phase 1 才把此狀態接上作品切換與圖文工作台。
- 私人檔案路徑確定為 `Works/<作品>/Visual/<entry-id>/`，內含 `content.md`、`metadata.json` 與 `assets/`。標題改名不改動固定 ID 路徑。
- 圖文圖片使用 `./assets/<stored-name>` 相對路徑；adapter 接受既有圖片的 `fileName`／`size`，正規化為 `storedName`／`bytes`，方便沿用目前匯入能力。
- 共用發布層使用 publishable view model。長文仍保留原本 `chapter`／`part`，圖文仍保留 `visualEntry`；adapter 回傳共同的標題、正文、圖片、平台標題、平台狀態與發布紀錄，不修改來源物件。
- 外層 workspace schema 維持 version 2。Phase 0 沒有開放圖文建立、切換、保存或刪除，因此也沒有新增半完成的介面入口。

### Phase 1：可用的圖文 MVP

- [x] 建立作品時選擇類型。
- [x] 圖文清單、新增、編輯、改名與刪除。
- [x] 標題、正文、圖片匯入、封面、圖說、替代文字與拖曳／按鈕排序。
- [x] 私人檔案輸出、workspace 保存與 Recovery。
- [x] 基本預覽。

#### Phase 1 決策紀錄（2026-08-28）

- 正文採純文字／Markdown 輸入與閱讀式預覽，不加入富文字工具列。
- MVP 使用一張封面加有順序的圖片，不加入段落錨點。
- 建立空系列時提供「同時新增第一則圖文」選項，預設開啟。
- 長文與圖文維持不同作品類型，不開放已有內容後一鍵轉換，也不加入混合作品。
- 圖文刪除前先建立 workspace Recovery；文字輸出另存 Recovery artifact，私人 assets 預設保留。明確刪除圖片檔時，先備份至 `Recovery/Assets/`。
- 手機唯讀模式可閱讀與預覽，但新增、編輯、匯入、排序、移除與保存都由既有安全層阻擋。

### Phase 2：整合發布

- [x] 圖文加入共用發布清單與篩選。
- [x] 平台標題、預覽／複製、發布紀錄。
- [x] 圖片上傳順序清單與檔案遺失提示。
- [x] 「繼續發布」與全域搜尋整合。

#### Phase 2 決策紀錄（2026-08-28）

- 共用發布頁使用「項」作為長文與圖文的中性數量單位，圖文在分組中顯示為「圖文清單」。
- 圖文不使用長文的「預覽預設設定」詞彙，主動作為「預覽／複製」與「管理發布」。
- 複製只包含文字與選擇的標題格式；圖片以封面與順序清單呈現，並明示需手動上傳。
- 圖片預覽使用私人檔案的暫時 object URL，對話框關閉後立即釋放。
- 工作台只在圖文成功保存、狀態為「可發布」，且具有標題與文字或圖片時顯示「前往發布」。

### Phase 3：只依真實使用再決定

- 圖文項目複製成新草稿。
- 替代文字完整性檢查。
- 平台特定的圖片數量或文字限制提示。
- 同一作品的混合內容模式，前提是已有多次真實需求。

## 12. 驗收範圍

Phase 1 可交付版本至少需通過：

1. 取消類型選擇不建立作品。
2. 既有 workspace 全部作品以長文模式正常開啟。
3. 圖文作品不顯示 Smart Split 操作。
4. 圖文新增、編輯、重新載入後的文字與圖片順序一致。
5. 改名不遺失圖片，同名檔不覆寫。
6. 刪除與刪圖操作在 Recovery 失敗時停止。
7. 手機唯讀可預覽，但不可儲存、匯入、排序或刪除。
8. 長文建立、來源更新、切篇、發布與既有圖片功能不回歸。

Phase 2 另需通過：

1. 長文與圖文能在同一發布頁篩選與開啟。
2. 平台標題、發布狀態與發布紀錄彼此獨立。
3. 複製文字不傳送圖檔，介面清楚告知圖片上傳順序。
4. 搜尋結果可開啟正確作品與圖文項目。

## 13. 後續使用觀察

Phase 1 已採用上述保守預設；下列方向只在真實使用顯示有需要時重新評估：

1. 有限富文字工具列是否比 Markdown 更符合實際編輯習慣。
2. 圖片是否真的需要正文段落錨點。
3. 建立空系列與同時新增第一則的使用比例。
4. 同一小說是否經常同時需要長文切篇與圖文宣傳貼文。

## 14. 何時應該改成另一個網站

目前不需要。只有在下列需求成為核心時，才重新評估拆分：

- 圖片要公開展示或提供網路圖庫。
- 圖片需要大量轉檔、縮圖、CDN 或雲端儲存。
- 需要多人協作、審核、權限或作業分派。
- 需要直接代表使用者發布至第三方平台。
- 圖文系統與 StoryFlow 作品、設定、素材與發布資料已完全沒有共用關係。

在這些條件出現前，同一 StoryFlow 內的雙工作台可提供最低的設定、資料與維護成本。
